# Lookout — 開發筆記

這份是**寫給要改程式的人**的設計筆記（繁體中文）：每一個行為為什麼長這樣、量過什麼、踩過什麼坑。
只是要安裝和使用的話，看 [README](../README.md)。

一般 macOS app：有 Dock 圖示、⌘Tab 找得到、不會永遠浮在最上層，也不會跟著你切到每一個桌面。
外觀照 **Mono Sharp** design system（`app/design/mono-sharp.tokens.json`）。

```bash
python3 app/gen_tokens.py   # 只有 app/design/mono-sharp.tokens.json 改了才需要
./install.sh                # 編譯並裝到 ~/Library/Application Support/Lookout/app/
```

⌘Q 或關掉視窗就結束。視窗位置與大小會自己記住。

## 在 Claude 裡開關（`plugin/`）

`plugin/` 是一個 Claude Code 外掛（mod）。它在每個聊天的**對話框正上方畫一列開關**
（「● Lookout 開著 ［關掉］」），也註冊 `/lookout`（`on`／`off`／`status`，不加參數就是切換）。
按鈕和指令走同一段程式（`setRunning`），兩邊的行為不會分岔。

**為什麼放在對話框上方**：mod 能畫的地方只有對話框上方那一列、側邊面板、對話紀錄裡的列、狀態列和 toast，
碰不到 app 本身的標題列和設定頁；狀態列只能放文字、按不下去。

**怎麼認出「就是那一個 Lookout」**：Lookout 啟動時拿 `instance.lock` 的檔案鎖，並把自己的 pid 寫進去。
mod 讀那個 pid，再用 `ps -p <pid> -o comm=` 確認它真的是 `lookout` 才算開著；關的時候只 `kill` 那一個 pid。
不用 `pgrep`／`pkill -x lookout`：用名稱比對可能認錯、甚至誤殺別的同名程式。
pid 被別的程式重用時也認得出來（測試裡有這一格）。

**狀態有四種，不是兩種**：`unknown`（還沒查過，開關列先不畫）、`running`、`stopped`、
`missing`（找不到 `install.sh` 裝的程式 —— 寫「還沒安裝」，不假裝成「關著」）。

**重新開機之後**：開關是開著的話，任何一個聊天開始時就會把 Lookout 打開。
開關記在 `~/Library/Application Support/Lookout/switch`（`on`／`off`），規則：

- Lookout 打開 → `on`
- **你自己**關掉它（關視窗、⌘Q、按「關掉」、`/lookout off`）→ `off`，之後不會自己跑出來
- 關機、重新開機、登出時被結束的不算你關的（app 收到 `willPowerOff` 就不寫）→ 維持 `on`

**跟啟動它的聊天脫鉤**：Lookout 啟動時呼叫 `setsid()`，自己一個 process group。
Claude 桌面版每個聊天的 engine 都跑在自己的 process group 裡，聊天結束時整組會被收掉，只用 `nohup` 擋不住
—— 實測舊版會跟著被關掉、新版留著。mod 也刻意不用 `$.process.spawn`（它的子程序會跟著 session 結束），
而是用 `$.process.run` 叫 `nohup … &`，程式路徑當成參數傳給 `sh`，不拼進指令字串。

**同時只會有一個視窗**：拿不到鎖就是已經有一個在跑，第二個直接結束。好幾個聊天同時開始、各自叫它一次也只會有一個。
鎖跟著程序走：當掉或被強制結束，鎖就放掉，不會留下假的「已經在跑」。

### 測試

```bash
claude plugin test plugin      # 需要支援 mod 的 Claude Code（2.1.317 測過）
```

terminal 和 desktop 兩種介面各跑一次，共 12 個：關著→打開→關掉（並寫 off）、剛重開機自動打開、
在別處 ⌘Q 之後 5 秒內跟上、pid 被別的程式重用時不認也不殺、還沒安裝時不畫按鈕、Claude 在問你問題時讓位。
**這組測試證明過會失敗**：把按鈕的兩個字對調 → 2 個變紅；拿掉「pid 是不是 lookout」的檢查 → 2 個變紅。
測試裡所有程序與檔案都是假的，不會碰到真的 Lookout。

**沒測到的**：真的重新開機一次（用「switch=on、程序不在」模擬）。

## Logo

`app/Logo.swift`。放射狀的等寬長條＋中心一個方塊：一個方框看著四面八方的工作。
只有 Dock 圖示用它（深色底、琥珀色的線、象牙白的方塊）；視窗標題列不放 logo 也不放名稱。

## 畫面

標題列什麼都不放，只有紅綠燈（視窗的 title 還在，「視窗」選單和 ⌘` 會用到）。底下一排**切換鈕**（Mono Sharp 的 FilterToggle）分成三區，
每一格寫著數量；點它切換，或用 **⌘1 ⌘2 ⌘3**。打開時有在等你的就停在「需要你」，沒有就停在「執行中」。

**會自動切換**，但只在事情發生的那一刻觸發一次：

- **有新的 session 進入「需要你」**：你在別的 tab，就切過去。
- **「需要你」從有東西變成空**（你把它們都處理完了）：你正在「需要你」，就切到「執行中」。

不是「只要有在等你的就停在需要你」—— 那樣的話，你主動切去看「執行中」時，2 秒後就會被拉回來，等於出不去。
同理，你自己點進一個本來就空的「需要你」，不會被彈走。2026-10-28 用假資料把這六種情況都跑過。

| 區 | 顏色 | 長什麼樣 | 排序 |
|---|---|---|---|
| **需要你** | 琥珀；卡在對話框的是紅 | 完整的列：標題、meta（「my-project · 已等 20 小時」）、狀態標籤、問題框 | **等最久的在最前面** |
| **執行中** | 綠，方塊會脈動 | 一行一個：標題、跑了多久 | 跑最久的在最前面 |
| **閒置** | 灰 | 一行一個，右邊寫「結案」或「無訊號」和多久之前（窄的時候見「文字排版」） | 最近的在最前面 |

顏色全部來自 Mono Sharp 自己的狀態色，對應的是它的定義，不是另外挑的：
卡在對話框＝`blocked`（被擋下，destructive 紅）、等你回覆／有問題＝`check`（需要人處理，warning 琥珀）、
執行中＝success 綠（tokens.json 對它的定義是「Done/passed/**live** status」）、閒置＝neutral 灰。
顏色出現在每一列最前面的小方塊、切換鈕每一格前面的 icon（需要你＝鈴鐺、執行中＝閃電、閒置＝月亮，線條版；有東西時「需要你」「執行中」的數字也用那個顏色），
以及懸停卡片的狀態行。

**對齊規則（全 app 一致）**：icon 或小方塊旁邊有文字時，一律放進固定大小的方框，並對齊**第一行文字的視覺中心**（基線往上半個大寫字高，`alignToFirstLine()`），不用外框置中或上緣對齊。內文行高是 1.625 倍，多出來的行距有一半在字的上方，所以「對齊上緣」會讓 icon 明顯偏高 —— 2026-10-28 問題框的警告三角形就是這樣比第一行高了 7.5pt。

量測（截圖量像素，100% 與 120% 字體）：問題框、摘要框、虛線框、列前面的方塊、切換鈕，icon 與第一行的垂直中心最多差 0.75pt（Retina 上 1.5 個像素）。量文字中心時要避開 g、p、y 這類往下延伸的字母 —— 它們會把文字中心拉低，讓 icon 看起來比實際偏高。

**某一區沒有東西時**，那一區的 icon、一行標題、一行說明（什麼時候會出現東西）由上往下排，
在列表剩下的空間裡上下左右置中，沒有框。Mono Sharp 的空狀態原本是虛線框，這裡照使用者的偏好拿掉。

**介面上的中文句子不加句點。** 需要分兩句時拆成兩行（例如空狀態的標題與說明），或用「·」「，」分隔。

**滑鼠停在任何一列上一下子，就會在那一列下方浮出完整內容**：完整標題、狀態、完整路徑、問題或摘要的全文。
不用系統的提示（toolTip），因為那個只在 app 是作用中時才出現，而這個視窗大部分時候是放在旁邊沒有焦點的。
滑鼠離開那一列後**等 0.3 秒**才收起來，這段時間移進卡片裡，卡片就會留著；離開卡片才收。

**session 問你問題時附了選項（`wrap_up` 的 actions），卡片上會有按鈕**：第一個是它建議的（實心主要按鈕），
其他是外框按鈕。滑過按鈕，下面會顯示按下去要送出的完整那句話。app 自己的動作（commit、開 PR…）從外面做不到，不會出現。

**同一個問題只能按一次**：按下的那一刻就上鎖，按鈕變灰；之後再打開卡片會寫「你已經用『…』回覆過這個問題」。只有確定什麼都沒送出（那句話只在剪貼簿裡）才解鎖；字已經貼進輸入框才停下的不解鎖，因為你可能自己按了 Enter。這一層獨立於上面的判斷：就算判斷又出錯，也不會送第二次。

**按下去 = 自動送進那個聊天。** Claude Desktop 沒有從外面送訊息進既有聊天的正式介面
（打開 session 的網址只轉送 23 個登入授權用的參數，`q`／`prompt` 只對開新聊天有效；
session 之間的訊息通道會被當成另一個 session 說的話），所以這裡模擬你本人操作：打開聊天、貼上、按 Enter。
模擬操作最怕送錯地方，所以 **Enter 之前每一關都要過**（`AutoSender`）：

1. Claude 網頁區塊的網址（輔助使用的 `AXURL`）裡出現目標 session 的 id —— 打開的確實是那個聊天
2. 那個聊天的輸入框是空的 —— 不會把你打到一半的草稿一起送出去
3. 焦點確實在那個輸入框上 —— 那一頁有一百多個按鈕，焦點不對時 Enter 會按到別的東西
4. 貼上後輸入框裡的字跟要送的那句完全一樣

按鍵用 `postToPid` 只送給 Claude，不送給「目前最前面的 app」。任何一關沒過就**不按 Enter**，
那句話留在剪貼簿或輸入框裡。用來貼上的剪貼簿會在送完後**還原成你原本的內容**（每一種格式都存）。
送完再讀那個 session 的對話紀錄，**看到那句話才算「已送達」**。結果**只顯示在卡片上**，停 6 秒才收。
原本也發一則系統通知，但那是借 `osascript` 發的，會以「工序指令編寫程式」的名義跳出來、每選一次就跳一次，
2026-10-28 依使用者要求拿掉。

需要「輔助使用」權限（系統設定 → 隱私權與安全性 → 輔助使用）。權限算在**啟動這支程式的 app** 頭上：
從 Claude 裡啟動就沿用 Claude 的、從終端機啟動就要給終端機。沒有權限時第一次按會跳出系統詢問，
那一次退回「複製並打開」。

「等你回覆」用 warning 語氣的提示框顯示問題原文，「有問題」用 info 語氣。
有些 session 的 `wrap_up` 只標了 `blocked`、沒有寫出 `ask`：這時提示框改顯示**那一輪的摘要**（`recap`），
並在最上面寫明「這是摘要，不是問題 · 它沒有寫出要問你什麼」。

## 捲軸與標題列

捲軸是自己畫的（`MonoScroller`）：直角、平常是一條 4pt 的淡色細線，滑鼠移上去時變 6pt、顏色加深並出現淡色軌道。
用 overlay 樣式，浮在內容上、不佔寬度。

標題列沒有 toolbar：只剩紅綠燈的細條，空間留給內容（2026-11-05 拿掉 logo 和名稱，截圖看過）。

## 未載入的 session

Claude Desktop 會結束閒置聊天的程序（2026-10-28 實測：闔上筆電過夜，隔天活著的程序全部是打開聊天之後才啟動的），
程序結束時它的狀態檔也一起被清掉。只看活著的程序的話，**一個還在等你回答的 session 會從畫面上安靜地消失**，
看起來跟「沒有東西在等你」一模一樣。

所以「需要你」區的 session 會被記在 `~/Library/Application Support/Lookout/remembered.json`。
程序結束之後，它繼續留在「需要你」區，下面多一個虛線框「未載入 · 打開它才會更新」。它會在這些時候消失：

- 你打開它（程序回來，換成正常的列，不會重複出現）
- 它的對話紀錄裡出現你的回覆
- 它的對話紀錄被刪掉
- 你在那一列按右鍵選「不再顯示這個 session」（例如那個聊天已經封存了）

只記「需要你」的，不記執行中或閒置的 —— 那些消失了也不會讓你漏掉什麼。
「等你核准」（卡在對話框）的未載入列，維持程序結束前最後看到的樣子，因為那件事從對話紀錄看不出來。
**這份記憶是從新版開始累積的**：新版之前就已經被結束的 session（例如 10-28 早上那一批）不在裡面，要打開它才會回來。

## 文字排版

Mono Sharp 規定標題 `text-wrap: balance`、段落 `text-wrap: pretty`。網頁一行 CSS 就有，AppKit 沒有，
所以 `paragraph()` 產生的多行文字一律是 `WrapField`，自己決定斷行：

- **置中的文字與標題用「平衡」**：找出不增加行數的最窄寬度，每一行一樣長（空狀態的說明、懸停卡片的標題）。
- **其他段落用「避免孤字」**：最後一行只剩 3 個字以內或不到 1/4 寬時，才稍微收窄，讓上一行分幾個字下來；盡量少收。
- **不拆詞**：用系統的中文斷詞（`CFStringTokenizer`）找出每個詞，在詞裡的漢字之間插入看不見的 U+2060，
  排版引擎就只會斷在詞與詞之間（原本會把「卡在」拆成「卡｜在」）。如果不拆詞會讓那段字多一行，就不做 ——
  多出來的那行可能被行數上限截掉，那比拆詞更糟。對外的 `stringValue` 給原文，不帶 U+2060。
- 做法是改段落的左右縮排，**不改文字框的寬度**：框照舊被約束撐滿，行數不變所以高度不變。
  文字框也**不回報內容寬度**（`intrinsicContentSize` 的寬是 `noIntrinsicMetric`）——
  否則平衡後內容變窄、框跟著變窄、再用更窄的寬度平衡一次，版面永遠收斂不了（第一版就是這樣當掉）。
- 最後由文字框自己的 cell 把關：收窄後如果變高了就放寬回去。量行數用的排版引擎和 cell 算高度，
  在換行邊界上會差 1、2pt（第一版：空狀態的說明畫成 2 行，框卻是 3 行高）。

**窄視窗或大字級時，空間不夠的地方讓出來，而不是互相擠壓：**

- 切換鈕：任何一格放不下「icon＋名稱＋數量」，三格一起只留 **icon＋數量**（數量用兩位數估，從 9 變 10 時不會來回切）。
  實測：寬 320 的 120%、160%，以及寬 420 的 160% 會收；其他維持有名稱。原本在寬 320·160% 會整組溢出、壓到隔壁格。
- 「需要你」的列：標題留不到 120pt 時收起右邊的狀態標籤。狀態還在 —— 列前面的色塊、所在的分頁、懸停卡片都寫著。
- 「執行中」「閒置」的列分三級：整句放右邊（「結案 · 40 分鐘前」）→ 只留時間（「40 分鐘前」）→ 時間移到標題下面一行。
  原本標題會被擠到只剩 2pt。
- 以上的判斷都只看列寬和字串寬，不看「現在怎麼擺」，所以不會因為切換本身而來回跳。
- 單行的列標題和 meta 照 Mono Sharp 的規格截斷（完整的在懸停卡片裡）；meta 從中間截，保住尾端的時間。

**行數上限**：問題框裡的問題 8 行（那是你要回答的東西）、摘要 4 行（全文在懸停卡片裡）；
「這是摘要，不是問題」那句說明、「未載入 · 打開它才會更新」改成可以換行 —— 它們是用來防止誤會的，不能被切掉。
懸停卡片底部原本有「點那一列在 Claude 打開」，使用者已經知道，2026-10-28 拿掉；
只在沒有連結（「不是從 Claude Desktop 開的」）或未載入（「右鍵可以不再顯示」）時才有底部那一行。

**檢查方式**（2026-10-28）：測試版在 9 種「寬度 × 字級」組合下，逐一打開三個分頁、三個空狀態、懸停卡片與 6 種送出結果，
共 117 個畫面，用跟畫面同一套排版引擎量每一段字，回報孤字、置中不平衡、截斷、拆詞、元件重疊，
並印出分母、拿排版行數對畫面高度自我檢查，再截 32 張圖人工看過。

| | 修前 | 修後 |
|---|---|---|
| 孤字 | 36 | 2（最窄最大字：最後一行 2、3 個字，但已佔 43–52% 寬） |
| 置中不平衡 | 12 | 0 |
| 拆詞（檢查的斷點數） | 43（143） | 4（160；都在 160% 字級，不拆詞會多一行，所以照規則拆） |
| 元件重疊（檢查的配對數） | 13（10989） | 0（9351） |
| 多行文字被截斷 | 7 | 4（都是摘要的 4 行上限，刻意的） |
| 排版行數與畫面不一致 | 1 | 0 |

## 套用 Mono Sharp 的方式

`design/mono-sharp.tokens.json` 是從 Claude 裡的 Mono Sharp design system artifact 原封複製過來的
（sha256 `ddff2cb46050db54…`）。`gen_tokens.py` 把它轉成 `MonoSharpTokens.swift`：

- **顏色是 oklch**，AppKit 不認得，產生器換算成 sRGB；sRGB 裝不下的 4 個狀態色
  （destructive 兩個主題、淺色的 success 與 warning）改用 **Display P3**，不裁切。
  換算結果對得上 README 自己寫的參照值（深色背景 `#09090b`、卡片 `#18181b`、淺色背景 `#ffffff`）。
- **不要手改 `MonoSharpTokens.swift`**：改 tokens.json 再重跑產生器。產生出來的檔頭記著來源的 sha256。
- **字體**：token 的順序是 `Inter → 系統字 → PingFang TC`。這台電腦沒有裝 Inter，所以用系統字；
  哪天裝了 Inter 就會自動用上，不用改程式。
- **圖示**：Mono Sharp 指定 lucide。這裡用外形最接近的 SF Symbols 線條版代替（不用填色版）。
- 照著做的規則：全直角、不用毛玻璃與陰影、列表不是一列一張卡而是用 1px 線分隔、
  狀態標籤三件式（文字色＋同色 10% 底＋同色 40% 框）、hover 填 `muted` 60%、
  箭頭 hover 右移 2px（0.15s）、執行中脈動 0.8s；系統開了「減少動態效果」時兩個動畫都關掉。
- 跟著系統的淺色／深色走，兩種都截圖確認過。

## 點擊跳轉

網址是 `claude://claude.ai/epitaxy/<hostSessionId>`，**不是猜的**：取自 Claude Desktop 自己的
session 清單 API 的 `link` 欄位（說明是「從 app 外面打開這個 session」），2026-10-27 對過 40 筆，
前綴全部相同。`claude://` 在這台電腦上只有 `/Applications/Claude.app` 處理。
沒有 `hostSessionId` 的 session（從終端機跑的 CLI）沒有連結，那一列點不下去、也沒有箭頭。

## 它在讀什麼

```
~/.claude/sessions/<pid>.json           狀態檔，有心跳。給「執行中」「等你核准」
~/.claude/projects/<slug>/<sid>.jsonl   transcript。給「等你回覆」「有問題」「結案」
```

**不跟 Claude 本體通訊、不是外掛、不花 token。** 它掛掉不會影響任何 session。

測試時可以用兩個環境變數把它指到假資料，不碰真的 `~/.claude` 和真的記憶檔：
`LOOKOUT_CLAUDE_HOME`（取代 `~/.claude`）、`LOOKOUT_MEMORY`（取代記憶檔路徑）。

`<slug>` 是 cwd 把斜線**和點**都換成破折號：
`…/app/.claude/worktrees/x` → `…-app--claude-worktrees-x`（兩個破折號）。

## 判斷規則

| 狀態 | 從哪裡判斷 |
|---|---|
| 執行中 | `status == "busy"` |
| 等你核准 | `status == "waiting"` |
| 等你回覆 | 最後一次 `wrap_up` 有 `blocked: true`，之後沒有你的訊息（沒寫 `ask` 時改顯示 `recap`） |
| 有問題 | 最後一次 `wrap_up` 有 `ask` 但沒 `blocked`，之後沒有你的訊息 |
| 結案 | 問題已被回答，或最後一次 `wrap_up` 什麼都沒問 |
| 無訊號 | transcript 裡沒有任何 `wrap_up` |

**「你的訊息」怎麼認**（`yourMessage()`）：看對話紀錄自己的 `origin.kind == "human"`。
2026-10-28 之前只認「content 是純字串、不是 meta」，兩個方向都錯：

- **漏掉你的回覆**：app 在你的訊息前面加一段系統提醒時（例如連動 session 的狀態），content 是
  「提醒區塊＋你的字」的清單；附圖片時也是清單。認不出你已經回覆 → 選項一直掛著 → **同一句被送了兩次**
  （「為 CSE PVE 主機建立備份排程」，09:58:59 與 10:07:03 UTC，36 份紀錄裡唯一的一處）。
- **誤收不是你的訊息**：side-session 通知、背景工作完成通知、壓縮後的接續摘要也都是 type=user 的純字串，
  會讓還沒回答的問題被判成已回覆、從「需要你」消失。

沒有 `origin` 欄位的舊紀錄才退回舊規則，並排除系統標籤開頭的訊息。13 種實際出現過的格式都有測試。

刻意這樣做的四件事：

1. **每一筆都 `kill(pid, 0)` 問作業系統程序還在不在。** 狀態檔不保證會被清掉。
2. **沒見過的 `status` 值歸「未知狀態」並原字串顯示，不當成「跑完了」。**
3. **判斷「等你回覆」要看 wrap_up 之後有沒有你的訊息。** 少了這一步，每一個你早就回答過的問題都會永遠掛著。
4. **第一次掃 transcript 是從尾端往前找，不是整份讀。** 整份讀要 14 秒，從尾端找 0.35 秒，
   逐筆比對過兩者結論相同（7 個比對、7 個相同）。之後只讀新增的 bytes。

## 提示音

**只有需要你的時候才出聲**：session 從別的狀態**進到**「需要你」的那一刻響一次。跑完了、開始跑都不出聲
（2026-10-29 使用者的決定：「怕通知的聲音太多會很吵」）。

| 進到需要你的是 | 聲音 |
|---|---|
| 卡在對話框 | 同一個音輕敲兩下（`woodlow-urgent.wav`） |
| 等你回覆、有問題 | 往上一個音（`woodlow-attention.wav`） |

- 已經在「需要你」裡面換狀態（有問題 → 等你回覆）不再響；開 app 的那一刻也不響（第一次讀到的 session 沒有「之前」）。
- 同一次更新有好幾個 session 一起進來，只響一次，取最要緊的（卡在對話框優先）。
- **靜音**：選單「顯示 → 提示音」，打勾＝開著，下次打開沿用。重新打開時會放一次，順便確認音量。
- 規則在 `onTransition()`，播放在 `ChimePlayer`。

**聲音是自己合成的**，沒有取樣任何 Mac 內建音效。`sounds/synth_soft.py` 只用 Python 標準函式庫，
重跑就能產生同樣的檔案；要調音高、長度、音量改那支再重跑，把 `woodlow-*.wav` 換掉就好。
音效檔要放在**執行檔旁邊的 `sounds/`**；找不到時啟動會在 stderr 印出缺哪個檔，不會默默變成沒有聲音。

挑選過程：第一版四組（木琴、拇指琴、電鋼琴、Mono）被說太尖、太高；第二版改成柔和版四組
（氣音、柔鐘、毛氈鋼琴、低木琴），選了低木琴。跟第一版比：感覺音高 964 Hz → 317 Hz、
第一個音的起音 2 ms → 4 ms（低木琴是柔和版裡最有顆粒感的一組）、峰值小 8 dB（-13／-15 dBFS）。

**測試**（2026-10-29）：用另一個執行檔名（設定分開存）、假的 session 資料、音量 0 跑完整的播放路徑，照 7 步劇本切換狀態：

| 步驟 | 預期 | 開著 | 靜音 |
|---|---|---|---|
| 開 app 時已經有 2 個在需要你 | 不響 | ✓ | ✓ |
| 執行中 → 等你回覆 | 往上一個音 | ✓ | ✓ 不響 |
| 執行中 → 卡在對話框 | 輕敲兩下 | ✓ | ✓ 不響 |
| 執行中 → 跑完了 | 不響 | ✓ | ✓ |
| 有問題 → 等你回覆 | 不響 | ✓ | ✓ |
| 需要你 → 執行中 | 不響 | ✓ | ✓ |
| 同一刻一個有問題、一個卡在對話框 | 只響一次，輕敲兩下 | ✓ | ✓ 不響 |

不發系統通知：選選項後的通知已經依使用者要求拿掉（借 osascript 發的通知會以「工序指令編寫程式」的名義跳出來），提示音也不搭配系統通知。
